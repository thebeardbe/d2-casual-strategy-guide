# Diablo II Map Codex

An interactive version of the act flowcharts from
[WithNoFiller's "The Code to Navigate Every Diablo 2 Map"](https://www.youtube.com/watch?v=J1EFUYGk4CA).

Pick an act, click any area on the chart, and you get that area's card: map type,
features (bosses, quests, super chests), where it is entered from, where it leads,
the turn rule, and an example layout captured from the video.

## Running it

```bash
npm install
npm run dev        # http://localhost:5173
```

Gates:

```bash
npm run typecheck
npm run lint
npm run test
npm run build      # static bundle in dist/
```

`npm run build` produces a plain static site: serve `dist/` from any web server.
Every view has its own URL (`#/act/1`, `#/act/1/jail-2`), so areas can be linked
and reloaded.

## Running it in Docker

```bash
docker compose up -d --build      # http://localhost:8080
PORT=9000 docker compose up -d    # different host port
docker compose down
```

Or without compose:

```bash
npm run docker:build             # docker build -t d2-map-codex .
npm run docker:run               # docker run --rm -p 8080:80 d2-map-codex
```

The image is a two-stage build: Node 24 compiles and typechecks the site, then
only the built files are copied into `nginx:alpine` (~75 MB). The container runs
read-only with a `no-new-privileges` policy, serves gzip-compressed assets,
caches hashed bundles for a year, and exposes `/healthz` for the built-in
healthcheck. No runtime configuration or volumes are needed.

## Keyboard

| Key | Action |
| --- | --- |
| `Left` / `Right` | previous / next area in the act |
| `Esc` | back to the chart |
| `Enter` / `Space` | open the focused chart node |
| `Tab` | move between chart nodes and tabs |

## How the data is organised

```
src/
  types.ts               Area, Connector, NavigationRule, Act
  data/
    mapTypes.json        the ten map-type classes: label, colour, one-line meaning
    act1/outdoor.ts      Act I outdoors, town through Tamoe Highland
    act1/dungeons.ts     Act I caves, cellars and dungeons (side areas)
    act1/monastery.ts    Act I, Monastery Gate through the Catacombs
    act1/index.ts        assembles the areas and the arrows for the act
    acts.ts              which acts are available, chart order helpers
  lib/
    layout.ts            chart geometry: node rectangles and arrow polygons
    route.ts             hash routing (#/act/1/jail-2)
    label.ts             label line breaking
  components/
    Flowchart.tsx        the SVG chart, nodes, arrows and legend
    AreaDetail.tsx       the framed info panel plus example map
    NavigationRule.tsx   fallback view when no example screenshot exists
```

Adding an act means adding one folder under `src/data/`, registering it in
`acts.ts`, and adding its example images to `public/examples/`. The tab bar
already lists all five acts; the ones without data are disabled on purpose.

Chart positions are stored per area as `row` (0 is the top row) and `column`
(fractional, so the layout matches the reference chart's uneven spacing). Nothing
is pixel-positioned by hand: `lib/layout.ts` turns the grid into rectangles and
arrow polygons, so the chart scales to any width.

## Example maps

Example images in `public/examples/` are frames from the source video, cropped to
the isometric map. They are generated by `tools/extract_cards.py`, which:

1. scans a window of seconds per area and scores every frame for "clean automap"
   (map lines on black, no gameplay HUD),
2. checks the frame's title box colour against the expected map type,
3. crops the map area and auto-detects the content bounding box,
4. writes a report to `tools/extract-report.json`.

`tools/cards.json` holds the per-area manifest: the id of the area, the map type
of the card (`cardType`, which is not always the area's own type), the seconds
window where that card is on screen, and optional `force` (pin one second) or
`allowLow` (accept a frame that failed the clean-automap check) overrides. Both
overrides are hand-checked exceptions; without one, a frame that fails the
title-colour check is reported as missing rather than shipped.

Areas where the video only shows gameplay footage have no example image and use
the navigation-rule fallback instead. `tools/extract-report.json` lists them under
`missing`, and `NOTES.md` records which ones still need a picture.

The video itself is not in the repository; the script's header documents how to
fetch and transcode the section it needs.

## Contributing

Issues and pull requests are welcome, especially corrections with a source.
Read `references/planning/` first: it holds the agreed direction, the data rules
and the recipe for finishing Acts II-V. Two rules that matter more than style:

1. **Every fact needs a source.** Area data links to the video timestamp it came
   from; build pages link to the guide or video. A number with no source is a bug.
2. **Say when something is not covered.** `"not covered"` is a valid answer;
   filling gaps from memory is not.

Run `npm run typecheck && npm run lint && npm run test && npm run build` before
opening a pull request.
